# GNU Make: Reading and Debugging a Broken Makefile

> In this exercise you get a `Makefile` for a small project that contains seven independent mistakes. Your job is not to rewrite it but to find and fix each one using the diagnostic tools of `make`: `-n`, `-p`, `--debug=b`, `--warn-undefined-variables` and careful reading. No `sudo` is required.

## Introduction

Most `Makefile`s you will deal with were written by someone else, often years ago. The lecture put it bluntly: you may never write one from scratch again, but you must be able to read one. Reading means being able to answer, for any target, three questions: what does it depend on, what will run, and why did it (not) run just now.

`make` can answer all three if you ask properly:

- `make -n target` shows the commands without running them.
- `make --debug=b` explains every decision ("must remake", "is newer than").
- `make -p` dumps the complete database of rules and variables after parsing, including built-in rules.
- `make --warn-undefined-variables` complains about typos in variable names, which otherwise silently expand to nothing.

## Tasks

### Task 1: Set Up the Broken Project

```bash
mkdir -p ~/make-broken && cd ~/make-broken
printf '#include <stdio.h>\n#include "greet.h"\nint main(void){ greet("world"); return 0; }\n' > main.c
printf '#include <stdio.h>\n#include "greet.h"\nvoid greet(const char *n){ printf("Hello, %%s!\\n", n); }\n' > greet.c
printf '#ifndef GREET_H\n#define GREET_H\nvoid greet(const char *name);\n#endif\n' > greet.h
```

Now create the `Makefile` **exactly** as shown, including the odd whitespace. Use `cat` with a heredoc so that tabs and spaces survive, then verify with `cat -A Makefile` (tabs show as `^I`):

```bash
cat > Makefile <<'EOF'
CC = gcc
CFLAGS = -Wall -Wextra -O2
SOURCES = $(wildcard *.c)
OBJECTS = $(SRCS:.c=.o)
TARGET = hello

all: $(TARGET) 

$(TARGET): $(OBJECTS)
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c greet.h
    $(CC) $(CFLAGS) -c $< -o $@

greet.h: main.o

clean:
	rm -f $(OBJECTS) $(TARGET)

install: $(TARGET)
	cp $(TARGET) $(PREFIX)/bin/

test: all
	./$(TARGET) | grep -q Hello && echo PASS

.PHONY: all clean
EOF
touch install test
```

### Task 2: First Contact

```bash
make
```

Read the first error. It names a line number. Open the `Makefile` in `vim`, jump to that line with `:<number>`, and check with `:set list` what kind of whitespace is in front of the command. Fix it.

### Task 3: The Empty Variable

```bash
make
make -n
make --warn-undefined-variables -n
```

The link line has no object files. The last command names the culprit. Fix the variable name and rebuild.

### Task 4: The Circular Dependency

```bash
make clean
make
```

Read the warning about a circular dependency. Draw the cycle on paper: which target depends on which? Decide which edge is wrong and remove it. Why is a header depending on an object file never meaningful?

### Task 5: Targets Shadowed by Files

```bash
make test
make install
```

Both do nothing useful. Run `ls` and look for files with the same names as the targets. Fix the `.PHONY` line, then remove the stray files.

### Task 6: Install Into Nowhere

```bash
make -n install
```

With `PREFIX` undefined, `cp` would write to `/bin/`, which fails without root, or worse, succeeds with it. Give `PREFIX` a safe default with `?=` and create the directory in the recipe:

```make
PREFIX ?= $(HOME)/.local
install: $(TARGET)
	mkdir -p $(PREFIX)/bin
	cp $(TARGET) $(PREFIX)/bin/
```

```bash
make install
~/.local/bin/hello
```

### Task 7: Trailing Whitespace in a Prerequisite List

```bash
make -p 2>/dev/null | grep -A2 '^all:'
```

Look at the line `all: $(TARGET) ` in the file: there is a space after `$(TARGET)`. Here it is harmless, but change it to `all: $(TARGET)\ ` (backslash-space) or put the whitespace inside a variable and watch `make` look for a target named ` `. Find the setting in `vim` that highlights trailing whitespace (`:set list` or `match ErrorMsg /\s\+$/`) and clean the file.

### Task 8: Compare With the Built-In Rules

Delete your `%.o: %.c greet.h` rule entirely and run:

```bash
make clean && make
make -p 2>/dev/null | grep -B2 -A3 '^%.o: %.c'
```

It still builds, because `make` has a built-in rule for `.o` from `.c` that uses `$(CC) $(CFLAGS) $(CPPFLAGS)`. Which dependency did you lose by deleting the rule, and how would you add it back without writing a recipe?

## Questions

- List the seven defects you fixed and, for each, the single `make` option or command that revealed it fastest.
- Why does an undefined variable expand to the empty string instead of causing an error by default?
- A circular dependency is a *warning*, not an error, and `make` drops one edge. Why is that dangerous?
- Why is a file named `test` in the source directory such a common accident?
- `make -p` prints several hundred lines even for this tiny project. Where do they come from?
- What is `CPPFLAGS` in the built-in rule, and how does it differ from `CFLAGS`?

## Advice

When a `Makefile` misbehaves, resist the urge to edit. Run `make -n`, then `make --debug=b`, then `make --warn-undefined-variables`. Nine times out of ten one of the three tells you exactly what is wrong before you have read the file.

The defects in this exercise are not invented. Each one appears regularly in real projects, and each is invisible to someone who only runs `make` and looks at the result.
